# 加性组合学 · 点化学习手册

把 Tao 和 Vu 的《Additive Combinatorics》（剑桥高等数学研究 105，532 页）拆成一套能按顺序学的材料：13 章精讲、14 篇跨章概念、45 道题、52 张抽认卡、52 条术语，外加模式库和速查表。打开根目录的 `index.html` 就能开始，不需要装任何东西。

## 为什么做这个

这本书不好读，不是因为难，是因为它的组织方式是“工具驱动”：先给你一套工具，再用它打一批问题，然后升级工具。按原书顺序硬啃，很容易出现每章都看懂了、合起来却说不清全书在干什么的状态。

所以我没有按原书章节做摘要，而是重排成三条线：**和集有多大（正向估计）— 和集小说明什么（逆向结构）— 工具怎么在两之间往返**。每一章开头都写清“这章解决什么问题、前置是什么”，末尾给自测题和三条复习锚点。读完一章，你应该能用自己的话讲出这章在全书里的位置，而不只是记住几个定理名。

## 怎么打开

最省事的方式：双击 `index.html`。

如果浏览器对本地文件的脚本有限制，起一个本地服务：

```bash
cd 加性组合学
python3 -m http.server 8000
# 打开 http://localhost:8000
```

Mermaid 图需要联网，脚本从 jsDelivr 拉 `mermaid@10`。断网时图的位置会显示源码，其余功能（导航、搜索、测验、卡片、进度）都正常。这一点我没法两全：把 Mermaid 连同字体一起内联会让单文件涨到几 MB，反而不好分享。

手机端顶栏下面有个「目录」按钮，点开才是章节列表，选完自动收起，不会挡着正文。

进度存在浏览器的 localStorage 里。换浏览器、清缓存会丢，这是设计如此，没有账号体系。

## 学习路径

完整顺序是 00 → 12，每章的前置写在章首。三条跳读路线，按你的方向选：

- **数论 / 组合方向**：00 → 01 → 02 → 04 → 05 → 10 → 11 → 12。核心是傅立叶、Freiman、密度增量。
- **几何 / 关联方向**：00 → 02 → 03 → 08 → 09。第 3 章的凸体与格点定理是第 8 章的地基。
- **概率 / 随机矩阵方向**：00 → 01 → 02 → 04 → 07。第 7 章的逆 Littlewood–Offord 直接通向随机矩阵奇异概率。

每章的检查点是章末三道题。做对两道算过，错的那道回看解析对应的概念段。跨章综合 6 题放在 `quiz.md` 末尾，建议读完 10、11 章之后再做。

## 写作上的取舍

**定理只讲“在干什么”，不抄编号。** 原书的定理编号对学习者没什么用，记住了也不知道怎么用。我改成“这个定理把什么转成什么、用的时候要核对哪个条件”。要精确表述，按上面的页码表回原书。

**定量界只给量级。** 比如 Roth 定理的界，原书从 log log N 讲到 (log N)^c，中间有很多版本。手册里只说“显式但很弱”，不给具体常数，因为那些常数依赖证明的细节，抄错一个指数就会误导人。

**例子都是自己算过的。** 比如 {1,2,3} 的 |A+A|=5、秩 3 长度 2 的 GAP 有 27 个点、p=7 时受限和集 {1,3,4} 恰好等于 2|A|−3、4×4 的网格 GAP 有 16 个点。这些数字我逐个验算过，不是从书上抄的。如果你发现算错，以你的计算为准，然后告诉我。

**图是概念图，不是证明图。** 13 张 Mermaid 图只表达概念之间的依赖和证明路线，不承载推导。想靠看图学会证明是不可能的，图的作用是让你在迷路时知道自己在哪。

**有些地方我做了简化，你要知道。** 第 5 章的“小挠”条件、第 10 章整数提升的细节、第 11 章 Gowers 逆定理的证明，都只讲了骨架。这些地方原书本身很技术，硬塞进零基础讲解会变成一锅粥。我的判断是：先让你知道有这一步、为什么需要它，细节留给你回原书时再啃。

## 别拿它当什么

- **不是原书的替代品。** 证明细节基本都省了，定理条件也做了口语化处理。真要引用，回原书。
- **不是速成课。** 13 章按每章 6–16 小时算，完整走一遍是 120 小时量级。想两天看完，只能看第 0 章和速查表。
- **测验只能查记忆。** 45 道全是单选，能确认你有没有记住“哪个工具对应哪类问题”，替代不了自己动手推一遍。
- **术语表不是词典。** 52 条只覆盖本书用到的概念，定义是白话版，不追求形式严格。

## 部署到 GitHub Pages

根目录已经放了 `.nojekyll`。这个文件必须保留：GitHub Pages 默认用 Jekyll 处理站点，Jekyll 会忽略以下划线开头的目录，`_work` 就会 404；关掉 Jekyll 才能原样托管。

```bash
cd 加性组合学
git init
git add .
git commit -m "additive combinatorics handbook"
git branch -M main
git remote add origin git@github.com:<你的用户名>/<仓库名>.git
git push -u origin main
```

然后到仓库的 Settings → Pages：

1. Source 选 “Deploy from a branch”。
2. Branch 选 `main`，目录选 `/ (root)`。
3. Save，等一两分钟。

访问 `https://<你的用户名>.github.io/<仓库名>/` 就是总入口。单书伴侣的地址是 `/01-加性组合学/加性组合学学习伴侣.html`，中文文件名在 Pages 上能正常访问，但分享链接时会被转义成一长串百分号编码，看着不美观。介意的话可以改名成 `companion.html`，同时改 `index.html` 里的链接——不过 `index.html` 是生成物，改完下次重建会被覆盖，正确做法是改 `manifest.json` 的 slug 再重跑。

更新内容时，改 `chapters/` 或 `concepts/` 里的 Markdown，然后重跑组装：

```bash
cd 01-加性组合学
python3 <skill>/scripts/build_companion.py --manifest manifest.json --out 加性组合学学习伴侣.html
cd ..
python3 <skill>/scripts/build_handbook.py --root .
```

`<skill>` 指 `book-enlighten` 技能目录。如果只改文字不重跑，`index.html` 不会更新——它是编译产物，不是运行时读取 Markdown。
